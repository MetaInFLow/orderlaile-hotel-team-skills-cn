# 订单来了 CLI 查询问题模板

订单来了 CLI 的 `query` 必须是完整中文自然语言问题，不能只传模糊关键词。

action 名称只用于内部路由，不直接替代自然语言问题。提交查询前，先确认门店、日期、对象、筛选条件、返回字段和统计口径；当前 App 页面可见但没有对应 action 时，转为人工页面或用户提供文件。

## 能力路由速查

| 用户意图 | 首选 action 组 | 问题中至少写明 |
|---|---|---|
| 房价、价格码、库存、超售 | `rate.*`、`rate_code.*`、`inventory.*` | 门店、入住日期、房型、价格码、渠道、返回当前值/变更日志 |
| 住宿订单、入住离店、排房、NoShow | `order.*`、`room.*`、`room_status.*`、`room_clean.*` | 门店、订单/客人定位信息、入住/离店日期、目标状态、返回字段 |
| 客户、会员、卡券、协议客户 | `customer.*`、`channel.*` | 门店、客户/企业/会员筛选、期间、返回订单或余额字段 |
| 营业、住宿、集团、销售、会员报表 | `report.*` | 门店、统计期间、指标口径、维度和下钻字段 |
| 流水、收银、AR、发票 | `finance.*`、`order.cashier_flow.query`、`order.account.query` | 门店、期间、账务对象、币种、含税口径、差异字段 |
| 房务任务、房态清扫、早餐、夜审 | `housekeeping.*`、`room_status.*`、`room_clean.*`、`setting.breakfast.*`、`setting.night_audit.*` | 门店、日期/班次、房间或任务、返回状态和责任人 |
| 员工、角色、权限、班次 | `user.*`、`auth.*`、`workshift.*` | 门店、员工/角色唯一定位、现状集合、变更差异 |

## 查询模板

```text
查询【门店名称】在【yyyy-MM-dd】至【yyyy-MM-dd】的【业务对象】，
按【房型 / 价格码 / 状态 / 客户 / 员工】筛选，
返回【需要的字段】并说明统计口径。
```

## 改价模板

```text
请查询【门店名称】在【yyyy-MM-dd】至【yyyy-MM-dd】、
【房型】、【价格码】的当前房价。
如果目标唯一，生成把价格从当前值调整为【目标价格】的变更预览；
不要执行，等待我确认。
```

## 改库存模板

```text
请查询【门店名称】在【yyyy-MM-dd】至【yyyy-MM-dd】、
【房型】的当前库存。
如果目标唯一，生成把库存调整为【目标库存】的逐日变更预览；
不要执行，等待我确认。
```

## 日报模板

```text
查询【门店名称】在【yyyy-MM-dd】的入住率、ADR、RevPAR、房费、
营业额、到店、离店、在住、取消、NoShow、房态异常和收银异常，
按日报口径汇总，并列出需要负责人处理的事项。
```

## 节假日模板

```text
查询【节假日名称】官方放假首日和末日。
最终 PMS 范围必须使用：放假首日前一天至放假末日。
先返回明确的 yyyy-MM-dd 日期范围，未确认前不要写入。
```

## 失败处理

查询异常、写入失败、异步部分失败时，停止当前流程。只能重新查询最终状态、展示失败明细和说明原因，不能自动重试。
