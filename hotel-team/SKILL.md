# 订单来了酒店团队总入口

## 触发条件

仅在用户要求“分析、判断、比较、预测、复盘、方案、计划、报告、看板、预警、交接、汇报、优化、落地清单”时使用。
用户只想查一个字段或执行一个已有操作时，不触发本 Skill，直接使用订单来了原生功能。
订单来了已经能完成的单点动作，不重复包装。

先识别酒店、岗位、业务对象、数据日期和是否写入，再路由：

- 总经理日报、经营会、风险、经营总览：总经理/运营总监
- 到店/离店结构、服务风险、走房方案、体验复盘：前厅/预订/宾客服务
- 需求判断、房价策略、渠道贡献、团队置换、收益预测：收益管理
- 收入差异、渠道结算、损益复盘、现金风险：财务/收入审计
- 餐饮增收、宴会方案、成本控制、人效计划：餐饮与宴会
- 房务效率、质量风险、维修优先级、资源计划：客房/房务/工程协同
- 团队机会、协议策略、营销计划、渠道内容、转化复盘：销售与营销
- 跨模块报表、看板、知识库、导出和管理层材料：数字化运营

## App 与 MCP 路由

先读取根目录 `docs/订单来了App与MCP能力映射.md`，再根据用户意图选择路径：

| 用户意图 | 路由 | 首选能力 |
|---|---|---|
| 只看一个 App 页面或查一个字段 | 订单来了原生单点入口 | 页面对应的 `so_cli` 查询；页面存在但 action 不存在时转人工页面 |
| 住宿订单、房态、排房、入住离店 | 前厅 / 客房 | `order.*`、`room.*`、`room_status.*`、`room_clean.*` |
| 房价、库存、价格码、渠道收益 | 营收 | `rate.*`、`rate_code.*`、`inventory.*`、住宿/营业报表 |
| 收入、流水、收银、AR、发票、现金 | 财务 | `order.cashier_flow.query`、`order.account.query`、`finance.*`、`report.*`、`wallet.*` |
| 房务任务、早餐、夜审、消费项 | 客房 / 餐饮 / 前厅 | `housekeeping.*`、`setting.breakfast.*`、`setting.night_audit.*`、`setting.room_consume.*` |
| 客户、会员、卡券、销售和渠道复盘 | 销售营销 | `customer.*`、`channel.*`、`report.sales_performance.query`、`report.member.query` |
| 多模块报告、经营会、跨店比较 | 总经理 / 数字运营 | `report.*`、按需组合各岗位 action 组 |

App 的 AI、营销、SCRM、短信、自动化消息、硬件、打印和客户端设置页面，若公共映射未列出对应完整 action，只能输出方案、清单或人工操作步骤，不得声称 MCP 已完成操作。

## 调度能力边界

能调度：`mcp__so_agents.so_cli`、明确需要的 `mcp__app_capabilities.pms_get_context`、已定义的跨店编排、明确授权的网页操作、本地文件产物和复杂任务的协作线程。
不能调度：未授权的网页点击、后台定时任务、海外连接器、用户级 Codex Skill 目录、未确认的 PMS 写操作。

统一执行：

1. 上下文缺失时先调用 `mcp__app_capabilities.pms_get_context`，只读取当前门店/网络和 baseUrl，不回显 token。
2. 实时 PMS/订单问题调用 `mcp__so_agents.so_cli`；完整 action 名称只作为内部路由依据，查询提交必须是完整中文自然语言问题。
3. `mcp__app_capabilities.pms_http_request` 只用于明确的跨店编排或已定义 Skill 的底层编排，不替代 `so_cli`。
4. `mcp__app_capabilities.execute_skill` 只执行已确认注册的 Smart-Order 业务 Skill；`ota_account_list` 只查 OTA 账号状态。
5. 日期统一为 `yyyy-MM-dd`；周末=周五、周六；平日/工作日=周日至周四。
6. 节假日范围=官方放假首日前一天 + 全部放假日期；不确定先确认。
7. 库存、房价、房态、渠道、订单写操作必须先展示完整影响范围，等待确认后执行。
8. 缺数据就写“暂无数据/待补充”，不编造；页面可见或接口返回成功但没有业务数据时，不得当作完成。
9. 不使用 Google Canvas、Google Drive、Gmail、Google Calendar、Canva、Vercel 等海外连接器。
10. 真实经营场景按模块拆分查询：先取核心经营指标，再按需取渠道、订单、房态和财务明细；不要把所有模块塞进一次 PMS 请求。
11. 输出前校验出租率、ADR、RevPAR、收入和间夜关系；口径冲突写明“口径冲突/待复核”。
12. 结论优先，输出：结论、关键数据、风险、动作清单。
